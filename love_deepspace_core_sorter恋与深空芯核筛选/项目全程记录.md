# 项目全记录：恋与深空芯核全自动筛选工具

## 一、需求提出

**原始需求：** 一个 Windows 脚本，通过 scrcpy 控制手机，自动遍历游戏中的芯核列表，OCR 识别副词条，根据阈值表反推强化次数，判定保留/丢弃。

## 二、初始开发

**文件：** `core_sorter.py`、`measure_coords.py`（OpenCV版）、`thresholds.py`、`requirements.txt`、`README.md`

**关键架构决策：**

- ADB 截图代替窗口截图：使用手机原生坐标系，不受 scrcpy 窗口位置影响
- OCR 用 PaddleOCR：支持中文，开源免费
- 控制用 ADB tap/swipe：通过 `adb shell input` 直接控制手机

**核心算法：**

- 枚举 N0 ∈ {2,3,4} 和所有强化次数组合，选偏离平均值最小的解
- 判定：全部词条达标 → 保留；任一条不达标 → 丢弃

## 三、环境踩坑

### PaddleOCR 版本不兼容

- 问题：PaddleOCR 3.5.0 + PaddlePaddle 3.3.1，报 `NotImplementedError: ConvertPirAttribute2RuntimeAttribute not support`
- 原因：PaddlePaddle 3.x 的 oneDNN 引擎不支持新版 PP-OCRv5 模型的 PIR 格式
- 尝试：设环境变量禁 oneDNN（无效）、换 PP-OCRv4（同样报错）
- 解决：降级到 PaddlePaddle 2.6.2 + PaddleOCR 2.9.1

### USB 驱动缺失

- 问题：荣耀 400 手机，Windows 缺 USB 驱动，adb devices 看不到设备
- 尝试：装 Google USB 驱动（权限不够）、各种 USB 模式切换（均无效）
- 解决：改用无线调试（adb pair + adb connect），绕过 USB 驱动问题

## 四、坐标测量

### OpenCV 窗口中文乱码
- OpenCV 的 Hershey 字体不支持中文
- 解决：用 Tkinter 重写测量工具（`measure_coords_tk.py`）

### 分阶段截屏太复杂
- 原设计：列表页、详情页两次截屏
- 用户反馈：一屏同时有详情和网格
- 简化：一次截屏，全部 12 个点标记

### 截屏按钮不响应
- 步骤名用"截屏"但代码检测"截图"，字符串不匹配
- 修复：检测条件从 `"截图" in title` 改为 `"截" in title`

### 完成步骤不保存
- 最后一步「完成」时 finish() 没被调用
- 修复：advance() 判断为最后一步时自动触发保存

## 五、核心功能

### `__init__` 结构被 `_log` 方法截断
- 加入 _log 辅助方法时缩进错误，OCR 初始化、统计变量、CSV 代码被吞
- 现象：控制面板报 `'CoreSorter' object has no attribute 'total'`
- 修复：把 _log 拆出去，确保 __init__ 完整

### 多设备冲突
- adb devices 有多个条目，screencap 报 `more than one device/emulator`
- 修复：增加 `_get_device()`，所有 ADB 命令加 `-s` 参数指定设备

### 判定规则修正
- 原代码：任一词条达标 → 保留
- 用户纠正：全部词条达标 → 保留，任一条不达标 → 丢弃

### 别名映射冲突
- "生命加成"和"攻击加成"都映射到 key "加成"，后者覆盖前者
- 修复：parse_stats 保留展示名作 key，get_candidate_times 和 get_threshold 内部先归一化

### 2 词条芯核被误报失败
- 代码要求至少 3 个词条才处理
- 修复：最低词条数从 3 降为 2

## 六、翻页/滑动

### 惯性导致距离不准
- 原设计手动测量起终点，游戏惯性导致大幅偏移
- 用户反馈：按住慢慢拖→停住→松手，就没有惯性

### 距离调优记录

| 距离 | 时长 | 结果 |
|---|---|---|
| sy × 3 (1044px) | 300ms | 翻过头 |
| sy × 2 (696px) | 500ms × 6次 | 翻少了 |
| sy × 2 (696px) | 5000ms 慢拖 | 翻少了 |
| sy × 2.5 (870px) | 5000ms | 翻少了 |
| sy × 2.6 (904px) | 5000ms | 翻少了 |
| sy × 2.8 (974px) | 5000ms | 翻过了 |
| **sy × 2.78 (974px)** | **5000ms** | **精准** |

### 关键洞察
超长 duration（5000ms）= 模拟「按住慢拖→停住→松手」，消除惯性，每次滑动距离可复现

## 七、UI 化

### 控制面板（`control_panel.py`）
- 开始/暂停/停止按钮
- 实时统计区（已处理、保留、丢弃、失败、速度）
- 运行日志区（每条芯核详细结果）

### 自动到底检测

- 暂时禁用，改由用户手动停止

## 十、关键经验总结

1. **版本兼容是第一坑** — PaddleOCR/PaddlePaddle 版本必须锁死，不能装最新的
2. **USB 驱动的坑可以绕** — 无线 ADB 完全可以取代 USB
3. **GUI 比终端友好太多** — 用户不需要记命令，点按钮就行
4. **滑动翻页要实测调参** — 游戏惯性滚动让距离+速度的组合调试了 7-8 轮
5. **缩进 bug 最难排查** — Python 缩进错误不会报错，只会让代码被错误地分配进方法体
6. **每次改动要确认重启** — 用户经常继续跑旧版本
7. **多设备记录会冲突** — ADB 可能残留旧连接，每次截图前要指定设备序列号
